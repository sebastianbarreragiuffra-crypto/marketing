## Rules

- Learn methods, not client content.
- Never copy keywords, copy, branding, layouts, metrics or private data across projects.
- Keep candidates compact.
- Use only OBSERVATION, CANDIDATE, VALIDATED LOCALLY, REJECTED, PROMOTED, SUPERSEDED or RETIRED.
- Mark weak candidates REJECTED when retaining the trace prevents repeated mistakes; remove pure noise when no useful trace remains.
- PROMOTED requires explicit user authorization plus verified canonical merge/release; authorization alone is insufficient.
- Automatic project-local capture/update is allowed after material work only when state persistence is ALLOWED; canonical writeback is never automatic.
- Canonical promotion requires explicit user authorization and release review.
